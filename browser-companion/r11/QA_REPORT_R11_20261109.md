# P029 Browser Companion R1.1 · QA evidence

**Date:** 2026-11-09  
**Decision:** Candidate integration confirmed in isolated environment. **Production release: HOLD.**

### Scope

Previously, \`browser_tabs({browser:"chrome"})\` enumerated empty isolated CDP tabs while hiding the user's already-open Chrome tabs. The R1.1 router now separates:

- \`USER_CONSENTED_TAB\` (current per-tab permission from the Browser Companion broker),
- \`ISOLATED_AUTOMATION_PROFILE\` (existing CDP targets),
- \`COMPANION_PAIRING_REQUIRED\`, \`USER_TAB_PERMISSION_REQUIRED\`, and \`COMPANION_UNAVAILABLE\` when access is not available.

The router protects access with the existing private Browser Bridge token and binds exclusively to localhost. It blocks content access and all write operations for user targets without the proper grant. Metadata of \`USER_NATIVE_UNATTACHED\` windows is excluded from tab discovery.

### Verified test runs

| System | What was actually run | Outcome |
| --- | --- | --- |
| Chrome for Testing 156.0.8078.47, headed Xvfb | Real MV3 worker, popup one-time code, Chrome action \`activeTab\`, selected-page read through R1.1, second tab refusal, manual and origin-change revocation | **10/10 PASS** |
| Original stock LUCH MCP adapter from the authorized runtime, run inside QA container | \`browser_tabs\` before/after pairing, \`browser_read_text\`, blocked \`browser_click\`, denied read after revocation, permission-visible \`browser_status\` | **7/7 PASS** |
| R1.1 router \`node --test\` | Auth, no native metadata leakage, pairing, isolation, wrong-browser/forbidden actions, unavailable CDP, fail-closed when both sources absent | **4/4 suites PASS** |
| R1 broker regression | Missing \`Origin\` on authenticated GET, origin/token errors and denial of unauthorized writes | **12/12 PASS in R1**, not new independent R1.1 audit |

Test pages were synthetic, on loopback, with synthetic pair code and synthetic MCP credentials. No personal cookies, credentials, Tilda/GetCourse data or live user Chrome tabs were copied or read. The stock adapter's **source files** were temporarily copied read-only for compatibility testing; they are not published in this branch and contained no credential/config files.

### Runtime routing

The following candidate-only ports were used in isolated tests:
- Browser Bridge mock: 9240
- Browser Companion broker: 9248
- R1.1 compatibility router: 9251
- Stock LUCH MCP adapter: 9243

The deployed MCP adapter on the actual paired Mac continues to use its existing production Bridge endpoint. Production LUCH Core, Chrome, Xcode and the user's sites were not changed.

### Remaining gates

1. Independent adversarial audit of tenant/device binding, origin/capability permissions, race conditions, and revoked in-flight reads.
2. Real user-driven extension installation and scoped grant on Chrome, including tab-switch, browser restart, renewal, and a clear user-visible revoke control.
3. Owner-authorized read-only checks on Tilda and GetCourse: proper tab inventory, correct domain and actual lesson descriptions.
4. Browser parity (at least Opera and Chrome), end-to-end latency, installer/signing/store review, rollback.
5. Explicit release approval before enabling the new router in the default Mac adapter or cloud LUCH.

**Do not report production PASS based on these engineering tests alone.**
