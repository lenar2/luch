# LUCH Browser Companion · Human Experience R14

**Состояние:** полноценный исходный UX-кандидат 0.8.4, не опубликован и не установлен в рабочий профиль. **Авторство:** работа в функциональном мандате AI-HEA / AIL-HEA-001; это НЕ подтверждение миграции/владения каноническим runtime AI-HEA.

## Что создаём для человека

Не «транспорт команд» и не «панель полномочий», а естественное продолжение привычного разговора с ИИ: подключить браузер, открыть нужные страницы, получить результат, остановить доступ в любой момент. Человек не обязан разбираться в PeerBus, CDP или OAuth, чтобы начать.

**Фраза продукта:** «Ваш ИИ может больше в браузере».

**Три простых состояния после установки:**

1. **Браузер ещё не связан с ИИ.** Пользователь сразу видит заголовок, откуда получить восьмизначный код, поле и кнопку. Основной CTA находится в первой видимой области (проверено: y=486–534 на viewport 410×615, без прокрутки). Подробное руководство раскрывается при желании.
2. **Связан, осталось разрешить Chrome.** Объяснение человеческим языком: читать страницы, нажимать и вводить текст, работать с загрузками. Честно сказано, что *полный режим* означает доступ ко всем обычным HTTP(S)-вкладкам, а системный диалог браузера требуется один раз. Основной CTA y=538–581 на viewport 410×615.
3. **Всё готово. Просто поручайте.** Показать реальный пример сообщения: «Прочитай открытую страницу и расскажи самое важное». Доступ остаётся до кнопки «Приостановить»/«Отключить» и автоматически восстанавливается после обычного перезапуска, пока действует ранее предоставленное разрешение.

**Особое состояние:** потеря связи не выглядит как потеря регистрации: «Связь прервалась. Настройки сохранены». Пользователь не получает ложного требования вводить код ещё раз. Отключение должно работать локально даже без интернета.

## Тексты и приватность

- Честная формулировка полного режима: **обычные веб-вкладки доступны до приостановки**, а не «только текущая вкладка».
- Не запрашиваем API `cookies` и `history`; по поручению содержимое страницы может передаваться вашему авторизованному AI-хосту.
- В первые 10 минут после выдачи кода он может быть введён один раз. Повторно привязывать браузер при кратковременном офлайне не нужно.
- Подключение возможно через поддерживаемый AI-хост с пользовательским MCP. Инструкцию о плане/тарифе оставить во вторичном слое, а не превращать главную кнопку в технический справочник.
- «Отключить» и «Приостановить» имеют разный смысл: первое разрывает сопряжение; второе останавливает управление, сохранив связь аккаунта.

## Фактическая проверка

- `node --test tests/*.test.mjs`: **55/55** portable PASS после исправления revoke race.
- `node security-qa.mjs`: **21/21** существующих негативных тестов PASS.
- `LUCH_TEST_PUPPETEER_CORE=... node --test audits/r14_sensitive_dom_e2e.test.mjs`: 1/1 реальный headless Chrome на синтетических секретах PASS.
- Реальные тесты команд из предшествующего R13: 19/19 в изолированной Opera (обновлённую 0.8.4 нужно повторно проверить после финальных правок).
- R13 event-driven benchmark: два обычных запроса заданий на 125 вкладках — **0 чтений всех вкладок, 0 обновлений значков**; при появлении новой вкладки — только она.
- **A1**: отмена мутаций после отзыва подтверждена новым unit race regression для `pin_tab`. Ещё требуется независимое adversarial тестирование всех остальных мутаций/платформ.
- **A2**: парольные значения и hidden/OTP/secret в `get_form_values` и `get_selected_html` больше не возвращаются на тестовых фикстурах; защита не равна гарантии от всех возможных сайтов.

## Что обязательно до пользовательского релиза

- Пройти честное первоначальное разрешение Chrome в **не-headless** тестовом профиле. Установлено только, что isolated headless Opera однажды ответила `Only permissions specified in the manifest may be requested`, тогда как с предварительно предоставленными разрешениями подключение работало.
- Пройти сквозной Cloud MVP (доставка вызова от хоста до расширения, фактическое выполнение и receipt), без непроверенных обещаний.
- Получить независимые QA/Critic проверки и реальную Human Experience приёмку на двух языках, короткий тест понятности с живым человеком.
- Не устанавливать поверх рабочего Browser Companion и не делать production deploy по одному красивому скриншоту.

## Для установки после приёмки

Человек подключает LUCH в своём привычном совместимом чате с ИИ → получает одноразовый код → вводит его в Browser Companion → один раз подтверждает системный доступ Chrome → даёт первое поручение. В дальнейшем — без нового кода и лишних всплывающих подтверждений, пока разрешение действует. Остановка — отдельной кнопкой в расширении.
