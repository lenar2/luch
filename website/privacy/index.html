Privacy Policy

This policy applies to the hosted LUCH Core service, the public LUCH Home web beta at /home/, and the LUCH client package published at this repository. LUCH is operated by its publisher, Lenar Salimov, as an individual. Core and device/AI tools remain limited-access. Public self-service registration is available specifically for LUCH Home's read-only website inspection beta; its account does not provide access to LUCH Core, devices or AI tools.

LUCH Home public beta · data and controls (23 November 2026)

Scope: The public LUCH Home beta is a separate account-based read-only website checker, not the restricted LUCH Core/AI device service. It does not connect SO 6.2, an AI account, an email service, private files or the user's device.

  • Account: chosen username, random-salted password hash, hashed recovery code (if issued), session hash, CSRF token and account creation time. A one-time recovery code is displayed to you and is not stored in readable form; losing both password and recovery code may make the account inaccessible.
  • Permission and results: the single public HTTPS domain you explicitly authorize for read-only GET /, permission issuance/revocation timestamps, the requested site's HTTP response status, title, HTML metadata, response time, bounded content hash, and timestamp. The checker does not follow redirects or download arbitrary private files.
  • Activity: event timestamps for account and permission operations, website checks, password resets, and revocations. The service does not collect an email address, card number or AI chat content in this beta. Infrastructure and diagnostic logs are subject to separate handling, described elsewhere in this policy.
  • Retention: website check records and in-app activity older than 90 days are excluded from account views and scheduled for database deletion at approximately 15-minute intervals while the app runs. Sessions expire after 14 days. Accounts, active grants and password/recovery hashes remain until account deletion; deletion in the app removes the account and related records from the live Home database. Other system logs or infrastructure copies may have different retention periods; this is not a universal deletion guarantee.
  • Control: you can revoke site permission, view your history, reset a password using the private saved recovery code, and delete the Home account and its associated active records in the Home interface. Home credentials are separate from LUCH Core credentials.

Website requests: if you authorize a domain, that public website sees the Home server's HTTPS request and may log it under its own policy. No model API is involved. Contact and privacy requests may be directed through the existing private reporting channel below; do not place passwords, recovery codes or sensitive data in public GitHub Issues.

LUCH Home: сведения для русскоязычных пользователей

Публичный Home — отдельная бета-версия для проверки главной страницы открытого HTTPS-сайта. AI, файлы и устройства не подключены. В Home хранятся выбранный логин, защищённый хеш пароля, хеш резервного кода, техническая сессия, разрешённый домен, результаты проверки и события. Адрес электронной почты и платёжные данные не запрашиваются. Проверки и история старше 90 дней скрываются из интерфейса и автоматически удаляются из базы во время работы сервиса с интервалом около 15 минут. Удаление аккаунта через интерфейс удаляет связанные записи из рабочей базы, но отдельные инфраструктурные журналы могут иметь другие сроки хранения. Доступ к сайту можно отозвать в любой момент.

What information is processed

  • Sign-in and identity: OAuth account identifiers and permitted identity attributes, which may include email and profile fields depending on the identity provider.
  • Device connections: device identifiers, names, pairing state, capability inventories and online status.
  • Actions requested: tool names and parameters, task/job identifiers, execution status, results, error details, timestamps and related metadata. Depending on the authorized tool, parameters or responses may contain page text, file content, device details, or other personal information.
  • Optional device media: for configured paired devices, limited photo/video metadata and search indexes can be cached. Original media is not part of the public client package.
  • Operations: connection metadata and security/diagnostic logs may be processed by the service and its infrastructure providers.

Why data is used

To authenticate users, enforce account/device permissions, carry out explicitly requested actions, display job results, investigate faults and security incidents, and maintain the service. LUCH does not sell personal information. The client plugin package does not collect account passwords. The separate Home web app receives passwords only through its own HTTPS authentication form and stores salted password hashes, not readable passwords. Do not include secrets in action arguments unless a tool explicitly requires them and you trust its destination.

Where data goes

LUCH uses Supabase for OAuth authentication and hosted infrastructure for operation. Authorized tool data may travel to external websites, connected devices and the AI host (such as Claude) from which you invoke the tool. Those services have their own privacy policies and may operate in different jurisdictions. The GitHub issue tracker is public: its contents are hosted by GitHub.

Retention and deletion

Completed durable execution jobs are eligible for deletion after approximately 7 days under the currently deployed job-cleanup logic; cleanup runs as subsequent durable state changes occur and the system also caps the number of completed jobs. This is not a guaranteed seven-day deletion deadline. Jobs still queued or running may remain until resolved or explicitly removed. Account/device pairing records remain while the account or pairing is maintained. Optional device media metadata caches can remain until refreshed or administratively removed. Security and infrastructure logs may have separate retention periods; a universal maximum has not been established. We do not claim zero retention.

For access, correction or deletion requests, use the private reporting channel and identify the request as a privacy request. Do not include passwords, tokens or sensitive files in an initial message. We may ask for confirmation of account control before acting. Some data must be retained temporarily for security or applicable legal requirements.

Security and user control

The public MCP endpoint uses HTTPS and authorization. Access to a device or account depends on its connection and grants; a plugin installation does not automatically grant device access. Any tool response delivered to Claude is also subject to Claude's own retention and privacy practices. Revoke a grant or disconnect a device to stop future permitted access; this does not automatically delete historical records.

Changes and contact

We publish material changes on this page with an updated effective date. For non-sensitive questions use GitHub Issues; for confidential security or privacy matters use private reporting. These channels require a GitHub account. Please do not submit personal data in public issues.
